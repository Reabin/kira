# 自动阅读进度同步（597 版构建，待真机验证）

入口：设置 → 通用 → 阅读进度同步。默认关闭，可选择 **iCloud Drive** 或 **WebDAV**；同一时间使用一种方式。两台设备都需要安装包含此功能的 597 或更新版本、启用同步并选择同一云端位置。旧的 1.7.4+596 安装包不包含本次新增功能。

## iCloud Drive

适用于 iPhone / iPad 的用户授权文件夹方式，不接入 CloudKit，也不新增 iCloud 容器或推送签名权限。

1. 在「文件」应用的 iCloud Drive 中创建专用文件夹，例如 `Kira阅读进度`。
2. 在本应用选择该文件夹，然后开启自动同步。
3. 在另一台设备登录同一个 iCloud 账号，在本应用选择同一个文件夹并开启同步。

每台设备单独保存自己的文件夹授权；不传递授权书签或文件系统路径。授权过期、移动文件夹或系统撤销访问权限时，需要重新选择。选择器拒绝「我的 iPad / iPhone」中的本机文件夹，避免将本地保存误认为跨设备同步。

文件写入所选目录后，由 iCloud Drive 负责上传和下载。设置中的「最近交换」只表示程序成功读写了本机当前可用的云盘文件，不表示另一台设备已经收到；系统可能延迟文件传送。后台或强制退出后不保证即时同步，打开另一台设备后会重新尝试。

依据苹果的 [文件夹授权文档](https://developer.apple.com/documentation/uikit/providing-access-to-directories)，使用 `UIDocumentPickerViewController`、持久化最小授权书签、`startAccessingSecurityScopedResource` 和 `NSFileCoordinator`。文件协调运行于独立串行队列，不阻塞界面线程。不依赖付费开发者账号的 CloudKit 能力。

**验证边界：**Dart 同步、存储、界面和原生通道参数测试已通过；597 版 Swift 桥接已通过 Xcode 真机 Release 编译，通用安装包已下载核验。尚未在免费账号 AltStore 安装的设备上验证授权持久化和真实云盘传送，仍需两台真机验收，不能将模拟云盘测试视为 iCloud 跨设备传送已可用。

## WebDAV

复用「备份」页面保存的服务器、目录和账号，并要求 WebDAV 总开关开启。无需开启定时备份。每台设备的服务器、账号、备份目录须指向相同位置。

阅读进度文件写入备份目录下独立的 `kira-progress-v1/` 子目录，不混入完整备份列表。上传先写临时文件，再通过 WebDAV MOVE 替换本设备文件；失败清理临时文件，保留原文件。服务器需要支持 PROPFIND、MKCOL、GET、PUT、MOVE 和 DELETE。

完整备份、密码加密、定时备份以及手动下载恢复均保持原逻辑。**进度同步文件不沿用完整备份的密码加密**，以普通 JSON 存在所选云盘中；WebDAV 凭据、漫画图片、小说正文、签名正文地址及封面地址不写入这些文件。

切换同步方式不会自动迁移另一种服务里的全部文件；新位置首次合并本机记录，遇到不同进度时要求选择。

## 自动触发与冲突处理

- 启动、返回前台、离开阅读页及读取继续阅读位置前尝试交换；前台每 30 秒检查一次远端变化。
- 本地进度落盘后等待约 5 秒合并连续变化，再尝试上传。离开应用时尽力提交，iOS 挂起后不承诺继续执行。
- 每次读取远端前先持久化本机待上传记录；网络失败保留队列，之后重试。进程关闭后仍可恢复待上传内容。
- 漫画保存作品、分组、章节和原始图片页码；横屏双页不使用双页组编号。轻小说保存卷、原始目录索引和段落位置，与屏幕尺寸无关。
- 已读章节／卷标记合并为并集。只打开同一阅读位置、刷新时间戳不会生成新的进度修改。
- 使用设备逻辑版本判断前后关系，支持主动回到前面的章节重读；不取最大页码，也不依赖设备时钟决定谁覆盖谁。
- 多台设备在互不知道对方修改的情况下改变同一本书的位置，会保留冲突并显示提示。在同步设置中选择要保留的位置后，才产生覆盖两边旧版本的合并记录。
- 阅读过程中可上传本机进度，但不将远端位置强行应用到当前阅读器；离开阅读器后再合并。等待网络时发生的新翻页通过串行队列及原值比较保护。
- 清理本机历史只作用于本机，不删除其他设备记录；同一云端旧版本不会立即将本机清理的条目恢复，另一设备产生新进度后仍可能重新出现。这里不是跨设备历史删除功能。
- 完整备份恢复期间暂停进度交换，避免恢复和远端写入交错。

## 协议与存储

`lib/sync/` 为独立模块，提供进度白名单、逻辑版本、存储适配、同步协调和两种传输。云端文件名 `kira-progress-<32位设备ID>.json`，每个安装实例只写自己的文件。每部作品携带已观察版本向量；单设备文件中只记录该设备主动改变过的作品。不会整库替换 SharedPreferences。

`progress_sync_enabled`、`progress_sync_backend` 与 `progress_sync_state_v1_<目标摘要>` 为本机配置及持久化待同步状态，不在普通设置备份白名单内。不同云端位置使用不同基线。iOS 使用设备标识隔离本机状态，避免系统迁移设备数据后两台设备写同一文件。

已读取的设备版本保存在本机，云盘暂时返回较旧文件或缺少文件时不回退进度。拒绝不支持的协议版本、无效身份、文件名与设备不符、同设备同版本但不同内容、损坏 JSON 及超限文件，不将读取失败当成空库。

单文件上限 8 MB、单次云端读取上限 16 MB、最多 100 个设备文件。协议是本项目专用，不自动兼容其他阅读器或它们的完整备份格式。

## 真机验收

598 版针对「文件夹选择器点打开后没有反馈」做兼容性修正：全屏呈现选择器，显式保留选择器和代理；收到选择后先关闭窗口，再在后台读取云盘属性并保存授权。授权处理超过 20 秒返回可重试错误，超时后的迟到结果不能覆盖新选择。取消和系统关闭均完成回调；应用内显示等待进度。云盘读写绑定选择时的文件夹身份，切换目录不会将旧任务改写到新目录。这些修正仍需针对原报告的真机现象复测。

在不删除现有应用的前提下先保存完整备份。两台设备选择相同同步位置后检查：A 翻页 → 离开阅读 → 等待文件到达 → B 打开继续阅读；B 倒回重读后 A 能接续较前位置；双方离线翻到不同页后出现选择入口；播放音乐、锁屏、切换应用和重新打开后不丢失本机位置。iCloud 还需检查冷启动授权保留、未下载文件的读取、授权撤销和重新选择文件夹。
